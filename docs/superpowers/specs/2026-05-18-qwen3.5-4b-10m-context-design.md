## 1. 项目定义

**一句话：** 在 16×H100 (2×8 IB) 约束下，把 Qwen3.5-4B 从「YaRN static 1M」推到「dense 2M-4M reader + hierarchical retrieval 端到端处理 10M」，主场景为长文档/多文档研究 QA，3 个月交付内部可用 MVP。

**核心论点：**
- Qwen3.5-4B 自带 256K native + YaRN→1M 是 **static**，长尾真实任务质量大概率虚高。需要 **有数据驱动的 CPT** 才能让 1M-4M dense 真实可用。
- Reader 自身 dense 上限定在 **2M-4M（主线 2M，4M 为 stretch boundary）**；超出部分由 hierarchical retrieval + query-aware compression 压到 reader 能消化的尺寸。
- Qwen3.5-4B 的 **gated delta networks (GDN) 混合架构**让 linear-attention 层在长序列上保持 O(N)，是相对 Llama-3.1-8B 这种纯 Transformer 的关键优势 —— 这是用 `flame` 框架训练的根本理由。

## 2. 关键决策（已确认）

| 维度 | 决策 |
|---|---|
| 10M 含义 | 系统端到端 10M（reader dense 2M-4M + retrieval 兜底其余） |
| 主场景 | 长文档 / 多文档研究 QA |
| 硬件 | 2 节点 × 8×H100 80GB + InfiniBand |
| 时间窗口 | 3 个月 MVP，交付内部可用系统 |
| Base model | Qwen3.5-4B（256K native, YaRN factor=4 → 1M） |
| CPT 训练框架 | flame ([fla-org/flame](https://github.com/fla-org/flame))，基于 torchtitan，FLA + GDN 友好；用于 Stage A/B/C |
| SFT 训练框架 | LLaMA-Factory ([hiyouga/LLaMA-Factory](https://github.com/hiyouga/LLaMA-Factory))，HF 生态成熟，DeepSpeed Ulysses 长序列支持；用于 Stage D/E |
| 后备框架 | Megatron-Core / NeMo（若 flame 在 CPT >1M 不稳）；TRL（若 LLaMA-Factory 在 SFT >256K 不稳） |
| 数据语言 | 英文为主 8:2（中文为 sanity，eval 双语都跑） |
| Reader dense 目标 | 主线 2M，stretch 4M |
| Retrieval 简化 | 只做 BM25 + dense + summary tree，graph/entity 第二阶段 |
| 算法"小改"范围 | YaRN 调参 / cross-doc attention mask / packing 格式 / length upsampling；**不改 attention 架构** |
| SFT 数据 | memory-format SFT 用 stronger teacher（Claude/GPT-5/Qwen3-72B）蒸馏 |

## 3. 整体架构

```
┌──────────────────── 推理路径 (Online Inference Pipeline) ────────────────────┐
│                                                                              │
│  Query                                                                       │
│    │                                                                         │
│    ▼                                                                         │
│  Query Processing  (normalize / rewrite / decompose / entity extract)        │
│    │                                                                         │
│    ▼                                                                         │
│  Hybrid Retrieval  ─►  BM25 top-200  +  Dense top-200  +  SummaryTree top-100│
│    │                                                                         │
│    ▼                                                                         │
│  Rerank  (bge-reranker / Qwen-based)  → top-40                               │
│    │                                                                         │
│    ▼                                                                         │
│  Neighbor Expansion  (prev/next chunk + section summary)                     │
│    │                                                                         │
│    ▼                                                                         │
│  Query-aware Compression  (用 self-trained reader)                            │
│    │                                                                         │
│    ▼                                                                         │
│  Order-preserving Packing  (按 doc / time / section 原序)                     │
│    │                                                                         │
│    ▼                                                                         │
│  Qwen3.5-4B Long-Context Reader (dense 2M-4M)                                │
│    │                                                                         │
│    ▼                                                                         │
│  Answer + evidence_ids + confidence + missing_information                    │
└──────────────────────────────────────────────────────────────────────────────┘

┌────────────────────── 离线索引 (Offline Indexing) ──────────────────────┐
│                                                                          │
│  Documents → Chunking (8K raw / 64K large / 512K section)                │
│    │                                                                     │
│    ├─► BM25 Index           (OpenSearch)                                 │
│    ├─► Dense Embedding      (FAISS + bge-m3 / jina-embeddings-v3)        │
│    └─► Summary Tree         (RAPTOR-style 递归摘要)                       │
│                                                                          │
└──────────────────────────────────────────────────────────────────────────┘
```

三层组件清单：

| Layer | 名称 | MVP 范围 |
|---|---|---|
| L1 | Long-Context Reader | Qwen3.5-4B + 长度扩展 CPT (1M/2M/4M) + 短 SFT + memory-format SFT |
| L2 | Hierarchical Retrieval | BM25 + FAISS dense + RAPTOR summary tree；**不做 graph/entity** |
| L3 | Inference Pipeline | rule-based router + 压缩 + 顺序 packing；vLLM / SGLang serving |

## 4. 训练方案

### 4.1 Stage 表

| Stage | 上下文 | YaRN factor | 训练 tokens | 数据重点 | 周次 | 成功标准 | 失败回滚 |
|---|---|---|---|---|---|---|---|
| **A. 1M CPT** | 1M | 4.0 | 50M smoke + 250M main | arXiv 全文 / 书 / 法律 / 多文档拼接 | W2-3 | RULER 1M ≥ +10pp over base+static YaRN | 降 lr，回滚 base+YaRN |
| **B. 2M CPT** | 2M | 8.0 | 150-200M | 同 A + 更多超长拼接 | W4-5 | RULER 2M multi-needle ≥ 70%，短任务退化 ≤ 3% | 停留在 1M reader |
| **C. 4M Boundary** *(stretch)* | 4M | 16.0 | 80-100M | 超长拼接 + 合成多跳 | W6-7 | 4M passkey + 2-needle 通过 | 终止，回滚 2M |
| **D. Short SFT Recovery** | 8K-32K | — | 30-50K examples | general / math / code | W8 | MMLU/GSM8K/HumanEval 退化 ≤ 2% | 减少 SFT 步数 |
| **E. Memory-format SFT** | 64K-512K | — | 15-20K examples | grounded multi-doc QA + citation | W9-10 | citation precision ≥ 80%；evidence recall ≥ 75% | 增大教师模型 / 重做数据 |

### 4.2 训练框架配置

**CPT (Stage A/B/C) — flame：**
- `flame` (torchtitan + FLA)，CP=16 跨节点 IB
  - `--experimental.context_parallel_degree=16`
  - `--experimental.context_parallel_rotate_method=allgather`
- 必开：bf16、FlashAttention (standard 层) + FLA kernel (GDN 层)、activation recomputation、optimizer state sharding (ZeRO-1)、async checkpoint
- `micro_batch=1` sequence，`gradient_accumulation` 把 global batch tokens 控制在 2M-4M
- 输出：HF-format checkpoint（torchtitan 原生支持），无需转换即可被 LLaMA-Factory 加载

**SFT (Stage D/E) — LLaMA-Factory：**
- 走 `llamafactory-cli train`，配置文件 yaml 格式（与 LF 标准对齐）
- Stage D short SFT (8K-32K)：DeepSpeed ZeRO-3，micro_batch=4
- Stage E memory-format SFT (64K-512K)：DeepSpeed Ulysses 序列并行 + ZeRO-3
- 数据格式：LF 的 `sharegpt` 或 `alpaca` 格式 jsonl；Stage E 用自定义模板把 spec §6.1 的 prompt 直接喂入
- Trainer：`Stage=sft`, `finetuning_type=full`（4B 可承受），`enable_liger_kernel=true`
- 后备：若 Stage E 512K 在 LF 不稳，回退到 TRL `SFTTrainer` + 自写 CP

**handoff：** flame CPT 输出 → `checkpoints/stage_X/latest/` (HF format) → LLaMA-Factory `model_name_or_path: checkpoints/stage_X/latest`

**回滚策略：**
- 1M CPT 卡顿即切 Megatron-Core
- 2M CPT 卡顿即增大 recompute；4M 卡顿即放弃 Stage C
- 512K memory-SFT 卡顿即降到 256K context，或切 TRL

### 4.3 算力粗算（H100 80GB，CP=16）

| Stage | 单 step (s) | Tokens/step | Steps | 纯训练时长 | 含调试 buffer (2.5x) |
|---|---|---|---|---|---|
| A.1M | 30-90 | ~1M | ~300 | 5h | ~12h |
| B.2M | 90-180 | ~2M | ~100 | 4h | ~10h |
| C.4M | 300-600 | ~4M | ~25 | 3h | ~8h |
| D.Short | < 30 | < 32K | ~few hundred | 2h | ~5h |
| E.Memory | 60-300 | ~256K avg | ~1k | 20h | ~50h |

**Total 训练时间预算：** ~85h × 16 GPU ≈ 1360 GPU-hours，对 16×H100 不到 4 天纯算力，但实际墙钟约 1.5-2 周（含数据准备、eval、failed runs、ckpt save/restore）。

### 4.4 数据混合（CPT，英文为主 8:2）

| 来源 | 比例 | 类型 |
|---|---|---|
| arXiv 全文 / 学术论文 | 20% | 长自然文档 |
| Books (PG-19 / Project Gutenberg / Books3 替代) | 15% | 超长叙事 |
| 多文档拼接（arXiv 同主题 / Wiki 主题包） | 20% | 跨文档建模 |
| 长技术文档 / Wiki / Pile-of-Law | 15% | 结构化长文 |
| 中文长文（WanJuan-Long / SkyPile-Long subset） | 10% | 中文 sanity |
| 合成 retrieval（needle + multi-needle） | 8% | 位置鲁棒 |
| 合成长推理（多跳 / 时间线 / 冲突检测） | 7% | 真实任务能力 |
| 短高质量保留 | 5% | 防退化 |

长度采样：< 4K 下采样、4K-8K 正常、8K-64K 上采样、64K-512K 强上采样、>512K 全保留。

### 4.5 算法"小改"清单（严格收敛于 3 个月）

1. **YaRN 调参 ablation**：factor / ramp-up / mscale，各 stage 扫一组（W2 / W4 / W6）
2. **Document packing 格式**：`<doc id=... source=...>` separator + cross-doc attention mask 开关
3. **Length upsampling 曲线**：在 64K-512K 区间扫 3 个比例
4. **不动 attention 架构**：保持 Qwen3.5-4B GDN/standard 配比原样

## 5. Retrieval 系统

### 5.1 Chunk 三层粒度

| 粒度 | 大小 | 用途 |
|---|---|---|
| raw_chunk | 8K tokens | BM25 / dense embedding / rerank 基本单元 |
| large_chunk | 64K tokens | 精读 / 邻居展开后的 packing 单元 |
| section | 512K tokens | 全局定位 / summary tree 叶节点 |

### 5.2 索引栈

- **BM25**: OpenSearch 单机部署
- **Dense**: FAISS HNSW + IVF；embedding 用 bge-m3（中英双语，FlagEmbedding 系列）
- **Summary Tree**: RAPTOR-style 递归摘要；用 Qwen3.5-4B（baseline）做摘要；树高 3 层
- **Storage**: PostgreSQL 存 chunk metadata + parent/sibling 关系

### 5.3 检索 pipeline

1. Query rewrite / decomposition（rule-based 先做）
2. Hybrid recall: BM25 top-200 ∪ Dense top-200 ∪ SummaryTree top-100 → dedupe → ~400 candidates
3. Rerank: bge-reranker-v2-m3 → top-40
4. Neighbor expansion: prev/next chunk + same-section summary → 合并相邻
5. Query-aware compression: 用 Qwen3.5-4B Instruct 抽取 `<evidence>` 块
6. Order-preserving packing: 按 doc / section / time 原序合并

### 5.4 Compression 格式

```xml
<evidence id="E01" source="S01" relevance="5">
  <claim>...</claim>
  <support_span>...</support_span>
  <why_relevant>...</why_relevant>
  <entities>...</entities>
  <time_or_version>...</time_or_version>
  <conflicts>...</conflicts>
</evidence>
```

压缩倍率目标：Raw retrieved 1-2M tokens → Compressed evidence 128K-512K → Reader input 128K-1M。

## 8. 风险与缓解

| # | 风险 | 缓解 |
|---|---|---|
| R1 | flame 在 >1M 长度上不稳 | W2 smoke 必须验过 1M；不稳即切 Megatron-Core，时间预算预留 1 周切换缓冲 |
| R2 | 2M dense 训练 OOM / 通信瓶颈 | 增大 activation recompute；改 selective recompute；最坏停留 1M reader |
| R3 | 4M 训不动 | Stage C 本来就标 stretch，不影响主交付 |
| R4 | static YaRN baseline 已经足够好（CPT 增量小） | 没关系，主要价值在 retrieval system + memory-format SFT |
| R5 | Memory-format SFT 数据生成成本高 | 用 Claude-Opus 或 Qwen3-72B-Instruct 做 teacher；先做 5K 跑 ablation，确认 ROI 再扩到 20K |
| R6 | 短任务退化 | 每 100 steps SFT 跑短 eval；保留 CPT checkpoint 随时回滚 |
| R7 | Retrieval recall 不足 | hybrid retrieval + neighbor expansion + 增大 top-k 后压缩 |
| R8 | 自建 10M benchmark 偏差 | 至少混合公开 LongBench v2 / InfiniteBench / NoCha 作 anchor |
| R9 | 时间预算超支 | Stage C 砍掉；Memory-format SFT 数据砍到 10K；retrieval 系统只保留 hybrid + summary tree |

## 12. 验收标准（MVP 完成定义）

- [ ] Qwen3.5-4B 训出 1M 稳定 reader，RULER 1M 显著优于 base+static YaRN
- [ ] 训出 2M reader（4M 为加分项）
- [ ] Memory-format SFT 后 evidence citation precision ≥ 80%
- [ ] Retrieval pipeline 端到端可跑，10M 输入到答案延迟 < 10 分钟（CPU+1 GPU reader）
- [ ] 10M 自建 benchmark 上方案 D ≥ 方案 B (Hybrid RAG) 至少 +5pp
- [ ] LongBench v2 / InfiniteBench / NoCha 中 reader 不退化（vs base instruct）
- [ ] 短能力 (MMLU/GSM8K/HumanEval) 退化 ≤ 2%
- [ ] 一份内部 tech report 草稿（10-15 页）
